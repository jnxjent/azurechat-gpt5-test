# TestSite 通常チャットのSF本人権限検索

## 方針

2026-10-22、利用者の指示により通常チャットのSF連携を、TestSiteのSF利用許可者全員について本人権限検索へ移行する。本番へのpush、merge、デプロイ、設定変更は禁止。

- `SF_PERSONAL_MODE=true` と `SF_PERSONAL_SCOPE=whitelist` で、既存の `SF_WHITELIST_EMAILS` 全員を本人検索へ送る。個別先行リストに載っていなくても共有接続へ戻らない。
- Microsoft認証済みprincipal/emailを署名し、テスト専用Gatewayの検証済みSF本人対応付けと照合する。
- 通常チャットの拡張からそのまま質問する。本人検索専用画面は必須ではない。
- 既存OAuth接続を再利用する。未接続者はチャット中のリンクから初回ログイン・許可が必要。SF外部アプリの権限セット割当だけではOAuthトークンは発行されない。
- 未接続、本人情報不足、権限不足、障害では検索を停止する。
- Teams/Skillsは本人検索への統合が済むまで停止を維持する。Webの設定を回避して共有検索はしない。

## 履歴とCanvas

既存データは削除・更新・一括分類しない。本人権限で出典を再検証できない旧回答・出典・Canvasは既存strict方針により非表示となる。新しい質問は通常チャットで実行できる。新規保存分は署名とSF出典証明を保存し、再表示時に現在権限を検査する。

通常チャットのCanvas作成と、専用検索から作る共有Canvasは別経路。通常チャットの任意Canvasを共有URLにする統合は、この切替だけで完成したと扱わない。

## 検証

対象者全員のルーティング、個別リスト未登録者、Microsoft principal不足、許可外ユーザー、OAuth接続入口、再接続案内、strict履歴、共有Canvasの回帰をローカルで検証。実ブラウザーでは通常チャットのSF拡張で本人検索とCanvas生成を確認する。
